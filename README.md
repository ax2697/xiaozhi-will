## 🧭 这是什么

**一份给 AI 助手执行的短剧 / 漫剧制作路由卡**（OpenClaw Skill / Agent 技能包）。

它本身不生产内容，而是一条**存取约定**：指令进来，先在卡上查清「读哪些文件的哪一节」，再去读你项目里的真实文件。

> 🔑 **核心立场**：**本卡不是读物，是路由。** 不要凭对话记忆动手——对话记忆一律视为过期，一切以磁盘当前 `.md` 为准。

它解决三个真实痛点：

1. **AI 不记得该读什么** —— 每次开工都要重新交代项目结构、资产在哪、SOP 在哪；本卡把这件事固化成一张表。
2. **两个文件冲突时不知道听谁** —— 提供 **8 条冲突仲裁优先级**（磁盘 > 记忆、`.md` > `.docx`、本剧 `.md` > 外部 skill 默认值 …），冲突有据可依。
3. **改了一处，下游全崩** —— 提供**改动联动表**：改了剧本要回头同步分镜、机位图、三资产包、情绪曲线，逐条列出。

> 📦 **本卡不持有你的剧**：它只带工作流与方法论骨架。角色 / 场景 / 道具 / 剧本 / 分镜，全部在你自己的项目目录里，由 `templates/` 里的 8 份空白模板起步。

## 🎯 适用场景

凡「**短剧 / 漫剧 / AI 视频**需要跨文件保持一致的制作流程」都适用：

- **AI 短剧 / 漫剧 / 短视频剧集** 的日常生产（本卡最典型的场景）
- 需要**出角色图 / 场景图 / 道具图**，且要求跨镜跨集形象一致
- 需要按 **10 字段分镜表** 出**关键帧**与 **Seedance 视频片段**
- 需要边写边**核对原著**（剧情三不铁律：不添加 / 不更改 / 不删除）
- 团队协作中，**多人（或多个 AI）交替接手**同一个项目
- 任何需要「**先读对文件再动手**」的多文件工程

## ⚙️ 快速开始

### 1. 安装（1 步）

把 `xiaozhi-will` **整个文件夹**复制到技能目录：

| 系统 | 路径 |
|---|---|
| Windows | `C:\Users\<你的用户名>\.workbuddy\skills\xiaozhi-will\` |
| macOS / Linux | `~/.workbuddy/skills/xiaozhi-will/` |

复制后不需要重启、不需要配置。在对话里说「**按路由卡执行**」「**这条指令该读哪些文件**」「**第 N 集开工**」「**新剧立项**」即可触发。

### 2. 建项目骨架

```bash
# 先看会建什么，不实际创建
python scripts/new_project_scaffold.py "<项目根目录>" --season 第一季 --episode 第1集 --dry-run

# 确认后真建（只新建缺失目录，绝不删除或覆盖任何已有文件）
python scripts/new_project_scaffold.py "<项目根目录>" --season 第一季 --episode 第1集

# 落盘 8 份模板并替换占位符（默认不覆盖已有文件）
python scripts/init_project_docs.py "<项目根目录>" --season 第一季 --episode 第1集
```

### 3. 替换占位符 + 锁 P0 参数

正文所有 `【方括号】` 都要换成本剧实际值，至少包括：
`【新剧名】【第N集】【题材】【主角】【常驻角色】【剧情源文件】【项目根目录】【画幅】【出图模型】【视频模型】【帧率】【风格】`

替换后把值写进**项目总索引参数卡**——它才是全项目「本剧锁定值」的唯一权威。

### 4. 给 AI 的最小执行序列

```
读 SKILL.md
  → 第 2 步查路由表：本次指令的第一依据是哪份文件
  → 第 2 步方法论先行：按产物类型读 references/09A–09E 命中章节
  → 读项目总索引参数卡 + 必读捆绑（精确到节）
  → 执行 + SOP 核验 + 方法论自检 + 下游联动
  → 报用户确认
```

## 🔒 三条总纪律

> 这三条写在 `references/README.md` 与 SKILL.md 第八章仲裁表里，是全部路由行为的判据。

| # | 纪律 | 含义 |
|:---:|:---|:---|
| ⓪ | **磁盘当前 `.md` ＞ 一切记忆与摘要** | AI 的对话记忆、上一次的摘要，一律视为过期，动手前必须 Read 磁盘 |
| ⑦ | **本剧 `.md` ＞ 外部 skill 方法论** | 外部三库只补方法，**不覆盖参数**。它的默认值（9:16 / R2 高燃 / 21:9 等）不得覆盖你锁定的本剧值 |
| ⑧ | **剧情源原文 ＞ 总纲 ＞ 分集大纲 / 剧本 / 分镜** | 三库均不得供剧情；剧情唯一来源是你的剧情源 |

## 🛡️ 安全说明

- **本技能自带 2 个脚本**，均 README 可查、均支持 `--dry-run`：
  - `scripts/new_project_scaffold.py` —— 只用 `os.makedirs` **新建目录**，不删除 / 不移动 / 不覆盖 / 不联网 / 不读凭据。
  - `scripts/init_project_docs.py` —— 复制模板到项目并替换占位符，**默认不覆盖已有文件**（需显式 `--force`）。

  > 说明：`init_project_docs.py` 帮助文本标为「只新建，不覆盖」，但实际存在 `--force` 覆盖开关。**不加 `--force` 时行为与说明一致。**
- **`external-libs/` 内的第三方脚本不会被本技能执行**，仅作资料保留，运行与否由你自己决定：
  - A 库 2 个 Python：`build_board_lite.py`、`check_fight_prompt.py`（本地文本检查）
  - C 库 8 个安装脚本：`安装课程包.ps1` / `新建AI影视项目.ps1` / `配置本地知识库.ps1` / `更新本地知识库.ps1` / `升级旧电影工程规则.ps1` + 3 个 `.command` + `install_course.py`
  - ⚠️ 这些是**洋子课程包的安装器**，会把 Skill 装进 Codex 的 `~/.codex/skills` 并写知识库路径。**运行前请先自己读一遍脚本内容。**
- 其余全是 Markdown 与一份原版 HTML 备份，无其它可执行代码。
