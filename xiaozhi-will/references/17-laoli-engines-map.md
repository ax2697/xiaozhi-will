# 17 · 漫剧老李套装 · 道教六阶归位图

> **来源**：`external-libs/D-laoli-suite/`（漫剧老李 V7.4.26 多技能套装版，MIT）
> **原结构**：1 总控 + 12 子技能 · 四层纵深
> **本文件做什么**：把老李的 12 个子技能**逐一归到我们的道教六阶**上，说清「这个引擎在哪一阶用、解决什么、和现有内容什么关系」。

---

## 一、为什么需要这张图

老李的套装是**按技能分**的（剧本引擎 / 资产引擎 / 分镜引擎 …），我们的体系是**按阶分**的（立鼎 / 采药 / 炼精 / 炼气 / 炼神 / 还虚）。

两套分类不对齐，直接拿过来就会变成"多了一堆文件夹，不知道什么时候用"。

**这张图就是翻译层**：你说"我在炼气阶卡住了"，能立刻查到该调哪个引擎。

## 三、逐引擎归位

### 一阶 · 立鼎（P0 立项）

| 引擎 | 原职责 | 归到哪 | 解决什么 | 我们的状态 |
|:---|:---|:---|:---|:---|
| **总控 〇·0 赛道分流** | 四赛道：国内剧 / 海外剧 / 解说类 / 其他 | 立鼎 · 定鼎器类型 | **立项第一问：做哪一类**。选错赛道，后面全套规则都错配 | ★ 无 |
| **总控 〇·1 素材来源锁** | 四来源：原创 / 改编 / 对标爆款 / 热点速成 | 立鼎 · 辨药物来源 | 药物（剧情源）从哪来，决定要不要走三不铁律、要不要采风 | ★ 无 |
| **sd-recon-engine** | 对标采风 · 情报卡十三项 · 六条证据纪律 | 立鼎 · 采药前置 | 用户说「对标某爆款」时，把公开信息找回来并按格式交付 | ★ 无 |

> **为什么这三项在立鼎**：立鼎是"安炉、定温、辨药"。赛道 = 炉型，来源 = 药从哪来，采风 = 上山采药。**这一步不定，后面全白做。**

---

### 二阶 · 采药（P1 剧本）

| 引擎 | 原职责 | 归到哪 | 解决什么 | 我们的状态 |
|:---|:---|:---|:---|:---|
| **sd-script-engine** | 六阶段编剧链：来源登记 → IP 与角色开发 → 开发圣经 → 分集规划 → 正式剧本 → 圆桌审核 | 采药 · 采真药 | 把"想法"炼成"可拍剧本"的六道工序 | ● 我们有 A 库六阶段要点，但无 6 份细则（共 250KB） |
| **sd-jieshuo-engine** | 解说/叙事类：旁白稿规范（4.5~6.5 字/秒）+ 声画信息差 + 历史视觉 | 采药 · 解说赛道专用 | **解说类的"台词"是旁白不是对白**。按剧情对白建模会系统性写错 | ★ 无 |
| **sd-overseas-engine** | 海外剧：语言契约 + 北美英语 + 平台受众 | 采药 · 海外赛道专用 | 海外剧不是"翻译一下"，是另一套语言契约 | ★ 无 |

> **关键洞察（老李原话）**：「同一套规则按剧情对白建模，会**系统性写错解说类**——语速口径错、篇幅卡口误判、分镜单位错、资产约束错位。」这正是我们缺的赛道意识。

---

### 三阶 · 炼精（P2 资产）

| 引擎 | 原职责 | 归到哪 | 解决什么 | 我们的状态 |
|:---|:---|:---|:---|:---|
| **sd-asset-engine** | 三包模板：人物肖像模板（52KB）/ 场景网格（26KB）/ 道具 / 三单提取（28KB）/ 连续性群像 | 炼精 · 精化气 | 把文字设定炼成标准化资产包的具体模板与提取法 | ● 我们有资产包骨架，但无这些具体模板 |

> **我们已补的部分**：v2.2.0 的 `14-anchor-coding.md`（@CHR/@SCN/@PRP 编码）正好补了老李资产引擎里"编号体系"的位置。两者互补：老李给模板结构，我们给统一主键。

---

### 四阶 · 炼气（P3 分镜）

| 引擎 | 原职责 | 归到哪 | 解决什么 | 我们的状态 |
|:---|:---|:---|:---|:---|
| **sd-decision-engine** | 情境映射 E01~E15 + 80/15/5 权重 + 情绪锚点表 + 构图雷区 A/B 双态 | 炼气 · **选型依据层** | 回答「**这场戏该用什么镜头**」——我们有"怎么拍"，一直缺"凭什么这么选" | ★ 无 |
| **sd-storyboard-engine** | 分镜：机位系统（54KB）+ 镜头经济与表演（41KB）+ P4.5 故事板预演 + 剧情推演网格 | 炼气 · 气成序 | 把选型落成可执行分镜表 | ● 我们有 10 字段分镜模板，但无镜头系统细则 |

> **这是老李套装最有价值的一块**。原文写得很准：
> 「全流程有'怎么拍'，但缺'**选型依据**'——同一场'女主鼓起勇气告白'的戏，到底该用长焦仰拍缓推，还是广角手持快摇？没有依据时，分镜设计全靠临场发挥，导致稳定性差、跨段不一致、情绪曲线无规划。」
>
> **这正是我们四阶·炼气化神的空洞。** v2.2.0 补了六把锁（怎么写），但没补"选哪个"（为什么）。老李补上了。

---

### 五阶 · 炼神（P4 生成）

| 引擎 | 原职责 | 归到哪 | 解决什么 | 我们的状态 |
|:---|:---|:---|:---|:---|
| **sd-feed-engine** | 投喂：七段式封装 + 六道投喂闸门 + 资产映射 + 工程语言清理 | 炼神 · 气化神 | 把分镜稿封成可直接投喂的提示词组 | ★ 无 |
| **sd-combat-engine** | 打戏：铁律（69KB）+ 招式库（81KB）+ 法术系统（46KB）+ 语法语料（46KB）+ 定级与终结技 | 炼神 · 打戏分支 | 打戏不是"加动作"，是一整套语法 | ★ 无 |
| **sd-xuanhuan-engine** | 玄幻：核心战斗法则 + 兵器参数库（36KB）+ 15 机位规格 + 宏大战场协议 | 炼神 · 玄幻分支 | 玄幻与写实是两套物理 | ★ 无 |
| **sd-real-engine** | 写实武打：运动链 11 环 + 真实格斗技术 + 防守闪避 + 多对手 + 渲染适配 | 炼神 · 写实分支 | 写实打戏要"真"，不能飘 | ★ 无 |

> **三大打戏引擎的分工**：老李分得很清——**写实（real）/ 玄幻（xuanhuan）/ 漫剧打斗（combat）**是三套不同的物理与语法。这解决了"所有打戏都拍成同一个味道"的问题。

---

### 六阶 · 还虚（P5 质检交付）

| 引擎 | 原职责 | 归到哪 | 解决什么 | 我们的状态 |
|:---|:---|:---|:---|:---|
| **sd-qc-engine** | 机检 C1~C33 + H1~H12（74KB 手册）+ 连续性台账 + 转场门 + 声音设计 + 阶段验收表 | 还虚 · 开炉验丹 | 把"看过觉得行"变成"逐条可判定" | ★ 无 |

> **机检 C1~C33 / H1~H12** 是老李最硬的部分——74KB 的机检手册，每条都是可判定的检查项。这比我们现有的"自检清单"细得多。

## 四、横向：老李的四层纵深

老李总控把 12 个引擎分成四层，这个分层值得保留：

| 层 | 含哪些 | 我们对应 |
|:---|:---|:---|
| **L0 锁层** | 〇·0 赛道 / 〇·1 来源 / A 模型 / B 画幅 / C 交付 / D 段缝 | 立鼎（我们叫"锁参数"） |
| **L1 决策层** | sd-decision-engine | 炼气 |
| **L2 生产层** | script / asset / storyboard | 采药 / 炼精 / 炼气 |
| **L3 执行层** | feed / combat / xuanhuan / real / qc | 炼神 / 还虚 |

> **我们的六阶是纵切（按时间），老李的四层是横切（按职责）。** 两者不冲突，可以并用：
> - 想知道**现在做到哪** → 看六阶
> - 想知道**这个活归谁管** → 看四层

## 五、六道前置锁（老李的锁系统）

老李有六道锁，全部在**立鼎**阶段一次锁死。我们取其中五道，与 P0 参数卡合并：

| 锁 | 老李定义 | 我们落在哪 |
|:--:|:---|:---|
| **〇·0 赛道** | ① 国内剧 ② 海外剧 ③ 解说类 ④ 其他 | 参数卡「赛道」字段（**新增**） |
| **〇·1 素材来源** | ① 原创 ② 改编 ③ 对标爆款 ④ 热点速成 | 参数卡「剧情源类型」字段（**新增**） |
| **A 模型版本** | Seedance 2.5 / 2.0 / MiniMax H3 三选一 | 参数卡「视频模型」（已有） |
| **B 画幅** | 6 档精确值 | 参数卡「画幅」（已有） |
| **C 交付形态** | 素材形态 M0 / M1 / M2 | 参数卡「交付形态」（**新增**） |
| **D 段缝衔接** | 段与段之间怎么接 | 参数卡「段缝策略」（**新增**） |

> **为什么这几道锁必须在立鼎**：锁是"炉温"。炉温中途改，前面炼的全废。老李把这一点做成硬前置，值得学。

## 六、冲突时听谁的

老李的套装和我们已有的内容有重叠（分镜、资产、剧本）。冲突处理：

| 优先级 | 规则 |
|:--:|:---|
| ① | **本剧磁盘 `.md` ＞ 一切外部包**（原仲裁⑦不变） |
| ② | **分工用老李，纪律用我们**：老李给"怎么做"的具体工艺，我们给"什么算做到"的判据 |
| ③ | **术语用我们统一的**：老李用「图N」编号，我们用 `@CHR/@SCN/@PRP`。用我们的 |
| ④ | **六把锁用我们的 15 号**，老李的 CINEDANCE 口径作为补充 |
| ⑤ | 老李的"套装契约"（不越界、不另立标准）予以保留 |

> **一句话**：**用老李的手艺，盖我们的章。** 手艺可以学，标准只有一个。

## 七、怎么用（三条路）

| 你要做什么 | 怎么走 |
|:---|:---|
| **正常做剧** | 不用管这张图。按 SKILL.md 六步流程走，需要时自然路由到对应引擎 |
| **某一阶卡住了** | 查本文件第三节，找到那一阶对应的引擎，直接进 `D-laoli-suite/<引擎名>/SKILL.md` |
| **想知道某个引擎具体讲什么** | 读该引擎的 `SKILL.md` 第一节「角色定位」+ 第七节「规则库索引」 |

```
我在炼气阶，分镜选型没依据
→ 查表：sd-decision-engine
→ 读：external-libs/D-laoli-suite/sd-decision-engine/SKILL.md

```
