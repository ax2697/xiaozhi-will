### 9.12 C 库：AI STUDIO 洋子 10-Skill 完整工程 V3（项目工程化总控 · 8 阶段创作链 · 本地知识桥）

> **定位：第三套外部方法库**，与 A 库（short-drama-director，定流程门与质检）、B 库（国外三库，定英文提示词工艺）并列——**C 库管"一个影视项目从零到交付怎么分阶段、在哪设门禁、怎么留版本、跨阶段怎么记忆"的工程化纪律**。**位置**：`..\工作流程\10步\`，双适配器：`01-Codex完整工程版\`（`skills\` 下 10 份 SKILL.md ＋ `project-template\` 工程模板 ＋ `scripts\`）与 `02-千问豆包OpenCode通用版\`（`01-通用总控系统指令.txt` ＋ `专业模块\01~08` 八个中文模块 ＋ `02-中文口令卡.txt` ＋ `本地知识库外挂\`）。本项目在豆包/OpenCode 类环境，**日常照 02 通用版的中文模块与口令走，需要某阶段完整细则时再查 01 版 `skills\<模块>\SKILL.md`**。**"10"的构成**：1 个弹性总控 `ai-film-router` ＋ 8 个创作阶段模块 ＋ 1 个本地知识桥 `film-knowledge-bridge`（第 10 能力，**不是第 09 创作阶段、不新增阶段、默认关闭**）。三库一句话分工：**A 库定流程门、B 库定提示词写法、C 库定工程组织与阶段门禁**；三者都只补方法，任何冲突一律按仲裁⑦：本项目磁盘 .md ＞ 外部库。

#### 9.12.2 首次入口门禁 A/B/C/D 与四种运行状态（只问一次）

### 四种入口

- **A 从零创作**：按 01→08 弹性推进——**本项目不走**（总纲已存在）。
- **B 已有完整标准剧本**：作者剧本锁定为最高事实，先出《作者剧本接管检查报告》（screenplay-intake-report：实际读取范围/集数场标题/缺哪些生产资料），用户确认"不改剧情只补生产资料"后才进 06，确认前不改剧本、不造资产、不批量拆镜头。
- **C 部分资料接力**：盘点现有资料，只补当前目标真正缺的，**不强迫重跑已确认阶段**。
- **D 高手镜头优化**：只处理点名的 06/07/08；先给修改方案、等用户确认方向，讨论不等于授权改。

### 四种运行状态 / 修订

- **全流程 / 指定阶段 / 接力 / 修订**；每完成一个阶段即停，"确认本阶段"才建议下一步，不自动连推。
- **修订模式**：切回上游只修指定问题 → 旧版入 `history/` 留档标版本号 → 列受影响下游并标"可能过期"，**不删、不自动重写** → 让用户选：只留新版 / 只重做受影响项 / 从指定阶段整体重跑。
- **本项目对应**：【剧情源】全文 ＋ 新总纲＝最高事实（等同 B 模式"作者剧本"地位）；单集走 C 接力：05 剧本→06→07→08；任何阶段发现剧情问题回 05 并按第十章三不核对剧情源，不擅改。

#### 9.12.4 08 CINEDANCE 内部两步门（硬门禁，与 9.3 六步、9.11 官方硬约束并行）

**第一步 · 镜头规划门**：给整场戏/整集时，必须先输出"场次时长核算 ＋ 镜头清单 ＋ 连续性台账"（落 05_shots ＝本项目分镜＋机位图），完整展示后**停下等确认**，用户确认前禁止批量生成视频提示词；只给单个已设计好的镜头时可直接写。 **第二步 · 模型适配**：C 库默认只问一次 A Seedance 2.0 / B MiniMax H3 / C 双版本——**本项目锁 seedance_2.5，跳过该菜单直接按本项目模型走，不再追问**。 **每条镜头提示词脱离聊天独立可懂**：禁用"上一镜头 / as before / continues"等省略式连续性词；纯文字模式展开完整起始状态，Lira 模式列本镜实际挂载资产，首尾帧模式用上镜尾帧或新机位首帧、同时写全文字（站位/姿势/道具/场景/光线/轴线/动作起点）。镜头以 3–10s 为主、容纳台词呼吸反应动作，不机械平均。
#### 9.12.5 第 10 能力 · 本地知识桥（默认关闭，主动调用才启用）

- **默认不提示、不检索**：只有用户明确说"调用本地知识库 / 知识库B / 知识库C / 匹配本地参考 / 只查方法书"才启用 film-knowledge-bridge。知识库 A＝直接回原流程；B＝智能匹配 3–5 部剧本或方法书（不需用户报片名）；C＝只查方法书。
- **跨阶段参考记忆**：确认采用的方法写入 reference-memory，编号"参考方法001、002…"，标使用范围（故事创作 01-05 / 图像 06 / 表演 07 / 视频镜头 08 / 全流程 01-08）；故事类方法在 01 或 04 确认后到 05 自动加载；未确认候选不入档；增加/停用/恢复/删除均留痕，普通删除只停用。
- **防污染铁律（与第十章三不同级）**：多部参考分工——一部只学结构、一部只学人物关系或冲突、一部只学氛围/表演/视听；**禁止拼接原作剧情，禁止 1:1 模仿人物身份组合、核心诡计、完整事件链、标志性场面、独创世界规则与长段对白**；知识卡先展示、等用户确认后才交专业模块。
- **本项目口径**：剧情唯一来源是【剧情源】（第十章），**不靠外部剧本库供剧情**；知识桥仅可在用户主动调用时用于学"结构/视听/表演方法"。脚本/SQLite 不可用或知识库未配置时，如实写"未调用本地知识库"，不得用模型记忆冒充本地命中。"配置/更新本地知识库、整理新剧本并更新知识库"属知识库维护、不进创作阶段（本项目一般不用）。

#### 9.12.6 C 库工程纪律六条（直接提级执行）

1. **一次只激活一个专业模块**，防编剧/视觉/表演/视频方法互相串味。
2. **无用户明确确认不改其他阶段已定内容**；要改先留版本（history/vNN）再改，用户可随时跳阶段、回退、局部重算。
3. 附件/图片/文档只有用户明确说"**以这些为准**"才成本轮权威；同名或冲突资料只问一次哪版有效，不自行混合。
4. 缺料只问当前阶段真正缺的**最小**资料，不强迫补齐整条流水线，不以"前序没跑完"为由要求重做。
5. 每阶段"**聊天完整展示 ＋ 同名内容落盘 md**"双交付（写清路径/版本号/本轮检查点）；修改先出新版本、留旧版、再展示，不能只丢文件路径。
6. **权威顺序**：用户本轮要求 ＞ 最新已确认项目文件 ＞ 启用的参考方法 ＞ 模型通用知识；中文口令驱动，不要求斜杠命令或英文阶段名。
