# 14 · 资产锚点编码体系（@CHR / @SCN / @PRP）

> **补的是原始路由卡 9.10.6 缺口清单第一梯队第 ② 项**——「三包统一 @CHR/@SCN/@PRP 锚点编码」。
> 原卡状态：「分镜表有 @CHR/@SCN/@PRP 但三包本身还无统一编码」——**引用方有码，被引用方没有**，这是断链。

---

## 一、为什么必须统一编码

现在的状态：

| 文件 | 有没有码 |
|---|---|
| 10 字段分镜表 | ✅ 有 `@CHR` `@SCN` `@PRP` |
| 角色包 | ❌ 无编码，靠"主角""常驻角色"这种叫法 |
| 场景包 | ❌ 无编码，靠 `S1` `S2` 这种序号 |
| 道具包 | ❌ 无编码，靠 `P01` `P02` |

**后果**：分镜写 `@CHR-主角`，但角色包里没有"主角"这个码。AI 要么猜，要么找不到，要么找到错的。跨集之后更乱——第 3 集叫"主角"，第 5 集换了个写法，就断链了。

**编码的本质是主键。** 主键不统一，关联就靠猜；一靠猜，下游全错。

---

## 二、编码格式

```
@<类型>-<剧集代号><序号>
```

| 字段 | 取值 | 说明 |
|---|---|---|
| **类型** | `CHR` / `SCN` / `PRP` | 角色 / 场景 / 道具 |
| **剧集代号** | 2–4 位大写字母 | 全剧唯一，立项时定死（如 `ZQ` 战起、`AN` 暗涌） |
| **序号** | 2 位数字 | 从 `01` 起，一经分配永不复用 |

### 示例

```
@CHR-ZQ01    林昭（主角）
@CHR-ZQ02    沈砚（常驻）
@CHR-ZQ03    老周（配角）
@SCN-ZQ01    祠堂正厅
@SCN-ZQ02    后院井台
@PRP-ZQ01    搪瓷缸
@PRP-ZQ02    钢笔
```

> **为什么带剧集代号**：多季多剧共用一套资产库时不会撞号。`@CHR-ZQ01` 和 `@CHR-AN01` 永远不冲突。

---

## 三、分配规则（立鼎阶段一次定死）

在 **一阶·立鼎** 建资产包时一次性分配，写进《项目总索引》的「资产锚点编码总表」——这是缺口清单里第 ⑦ 项要求的。

| 规则 | 说明 |
|:---|:---|
| **永不复用** | 某个码分配给某角色后，即使该角色删了，码也不给别的角色用（留空） |
| **不改号** | 一经分配不因改名、改设定而变号。改的是名字，不是码 |
| **一号一物** | 一个码只对应一个角色 / 场景 / 道具，不许一号多用 |
| **配角也发码** | 只要会出现在分镜里，就要发码。哪怕只出现一次 |
| **群演不发码** | "路人甲""士兵若干"不单独发码，用 `@EXT-<场号>` 占位 |
| **换装不换码** | 同一角色不同造型仍是同一个 `@CHR`，造型差异写在该角色 x.4 服装节 |

### 例外：集团角色

如果一组人始终同进同出、可视为一个视觉单元（如"四护卫"），发一个码 `@CHR-ZQ07`，内部成员在角色包内以 `07-a` `07-b` 区分。**但若其中某人单独有戏，必须拆出独立码。**

## 四、三包各自写在哪

### 角色包（02）

每个角色节标题下第一行写码：

```markdown
## x. 【主角】林昭

> **锚点码：`@CHR-ZQ01`** · 状态：🔒 已锁定 · 基准脸：`脸模/林昭_基准_v3.png`
```

### 场景包（03）

```markdown
## S1 祠堂正厅

> **锚点码：`@SCN-ZQ01`** · 状态：🔒 已锁定 · 六视图：`场景设计图/祠堂正厅/`
```

### 道具包（04）

```markdown
## P01 搪瓷缸

> **锚点码：`@PRP-ZQ01`** · 状态：🔒 已锁定 · 六视图：`道具设计图/搪瓷缸/`
```

### 总索引（01）· 编码总表

```markdown
## 资产锚点编码总表

| 码 | 名称 | 类型 | 首次出现 | 状态 | 基准文件 |
|---|---|---|---|---|---|
| @CHR-ZQ01 | 林昭 | 角色 | 第1集 | 🔒 | 脸模/林昭_基准_v3.png |
| @CHR-ZQ02 | 沈砚 | 角色 | 第1集 | 🔒 | 脸模/沈砚_基准_v2.png |
| @SCN-ZQ01 | 祠堂正厅 | 场景 | 第1集 | 🔒 | 场景设计图/祠堂正厅/ |
| @PRP-ZQ01 | 搪瓷缸 | 道具 | 第1集 | 🔒 | 道具设计图/搪瓷缸/ |
| @CHR-ZQ99 | （预留） | — | — | — | — |
```

> **预留码**：从 `90` 起留 10 个号给后期新增，避免临时插号打乱顺序。

## 五、分镜表怎么引

10 字段分镜的资产列**必须用码，不许用名字**：

| ❌ 错 | ✅ 对 |
|---|---|
| `角色：林昭、沈砚` | `角色：@CHR-ZQ01, @CHR-ZQ02` |
| `场景：祠堂正厅` | `场景：@SCN-ZQ01` |
| `道具：搪瓷缸` | `道具：@PRP-ZQ01` |

**理由**：名字会变（"林昭"可能改成"林昭之"），码不变。用名字引用，改名那天全表失效。

### 一镜多物怎么写

```
资产：@CHR-ZQ01（主）· @CHR-ZQ02（次）· @SCN-ZQ01 · @PRP-ZQ01（前景）
```

用 `（主）/（次）/（前景）/（背景）` 标注画面层级，供 P4 判断构图权重。

---

## 六、投喂时怎么用

在 Seedance / LIRA 的 Prompt 里，**码只出现在 Layer 1 全局不变量的资产锚点行**，不进画面描述正文：

```
Layer 1 · 全局不变量
画幅比例：16:9 横屏
模型版本：Seedance 2.5
核心角色/场景资产短锚点：@CHR-ZQ01 / @CHR-ZQ02 / @SCN-ZQ01 / @PRP-ZQ01
（必须指向已锁定资产图）
```

> **为什么不在正文写码**：模型不认识 `@CHR-ZQ01`。码的作用是**给人和给工具做映射**——投喂前用它去取对应的参考图，图作为独立输入传进去（见 SKILL.md「参考图独立输入」铁律）。
>
> **码不写进 prompt，图走独立输入。** 这是两件事。

## 七、状态标记

每个码必须带状态，状态决定能不能用：

| 标记 | 含义 | 能不能进分镜 |
|:--:|:---|:---|
| 🔒 | 已锁定，有唯一权威图 | ✅ 可以 |
| 🟡 | 已出图，待确认 | ⚠️ 可以出分镜，但不能进 P4 |
| ⬜ | 有设定，未出图 | ❌ 不可以（过不了三关·形关） |
| ❌ | 已废弃 | ❌ 不可以，需换码 |

> **形关判据**：所有进入本集分镜的码，状态必须是 🔒。有一个 ⬜ 或 🟡，形关不过。

## 九、一句话

> **名字是给人看的，码是给链路用的。**
> 改名不动码，码断了就找不到图——这是所有下游错误的起点。
